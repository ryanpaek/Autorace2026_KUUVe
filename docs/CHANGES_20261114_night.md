# 11/14 밤 (실차 요청 4건)

## 1. M7 전 횡단보도(M3)를 다 지난 뒤에 섬
- 정상 경로(지그재그 중 정지선 미리 재기 `m3_pretrack`, 도면 위치, 카메라 정지선)는 그대로 두고, **넘지 않게 하는 마지막 안전장치**를 추가.
- `m3_zz_cap`: 지그재그 시작선을 카메라(또는 도면)로 지난 순간부터 달린 거리로 정지선을 셈.
  도면 지그재그 시작선 → 정지선 1983 mm − `m3_zz_cap_target_mm`(100) − `stop_brake_mm`(30) 를 달리면 다른 판단과 상관없이 정지.
  카메라로 정지선을 잡으면 평소대로 `m3_stop_target_mm`(25 cm) 앞에서 먼저 섬.
- 로그: `M6_ZIGZAG ... stop line by zigzag-line distance NNNmm` 또는 `M3 stop by zigzag-line distance ... (stop line estimate ...)`
  → 이 로그가 보이면 정상 경로가 정지선을 놓친 것. 그때 bag을 주면 원인(카메라 횡단보도 인식 / 도면 위치)을 찾음.
- 시험: 카메라·도면 모두 정지선을 못 줄 때 예전엔 그냥 지나감 → 정지선 약 10 cm 앞 정지.

## 2. M7 차로 바꾸는 중 좌우 6~7번 지그재그
원인 (가짜 카메라 `/lane/status`를 넣은 시뮬레이션 `m7_pre_sim.py cam=True`로 재현, 40배치):
- **카메라 노란선 지킴**이 카메라 행(앞 0.55 m) 옆 위치로 판단 → 바깥 차로로 비스듬히 들어갈 때(차체는 아직 안쪽) 안쪽으로 끝까지 꺾음
  → 회피 조향이 다시 바깥으로 → 반복. 조향 뒤집힘 125번 중 지킴↔회피 64번.
- 옮기는 중 카메라 위치 고침(반만 반영)과 차선 노드 조향 섞기가 비스듬한 상태에서 회피 조향과 번갈아 이김.
- 막혔을 때 '빈 공간으로' 끝까지 꺾기·라이다 빈 길 찾기가 정한 차로 **반대쪽**으로도 감 (시험으로 확인: 3차선으로 정하고 왼쪽으로 전진).

고친 것 (`avoid_core.py`, `avoid_params.yaml`):
| 설정 | 내용 |
|---|---|
| `yellow_cam_body: true` | 카메라 선으로 **차체 앞 모서리** 위치·방향을 계산해 노란선에 닿거나 0.35 m 안에 닿을 때만 지킴 |
| `lane_fix_commit: true` | 정한 차로로 옮기는 중엔 카메라로 위치를 안 고침 (도착하고 펴지면 다시) |
| `lane_blend_max_psi_deg: 8` | 차선 노드 조향 섞기는 8° 안으로 펴진 뒤에만 |
| `squeeze_target_only: true` | 막혀 끝까지 꺾기·빈 길 찾기는 **정한 차로 쪽으로만**. 그쪽도 막히면 서서 후진으로 다시 봄 |

결과 (40배치, 가짜 카메라): 조향 뒤집힘 125 → 83 (판당 최대 11 → 4), 지킴↔회피 64 → 5, 성공·후진·시간 같음.
지연 0.15 s + 잡음: 105 → 86 (최대 7 → 6), 36 → 3. 남은 뒤집힘은 차로 하나 옮길 때 생기는 S자(왼→오) 한 번씩.
3차선 stress_sim 280/280 그대로. 예전으로: 위 네 값을 false/0.
