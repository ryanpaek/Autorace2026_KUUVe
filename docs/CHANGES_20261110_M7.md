# 11/10 M7 정적 장애물 회피 개선 (feat/m7-lane-id)

실차(11/10): 왼쪽 벽 때문에 장애물 12개, 왼쪽 차로 막힘 → 25cm 후진 탈출 3번 다 쓰고 멈춤. 차선 상태 L(한쪽만)이라 카메라 보정도 거의 안 들어감.

| 항목 | 바뀐 것 | 값 (avoid_params.yaml) |
|---|---|---|
| 몇 번 차로인지 | 차선 노드가 양쪽 선 종류를 봄: 왼쪽 노란 실선+오른쪽 흰 점선=1차선, 양쪽 흰 점선=2차선, 왼쪽 흰 점선+오른쪽 노란 실선=3차선. 7번 중 5번 같고 지금 추정과 다르면 그 차로로 위치를 옮김 (차로 바꾸는 중엔 안 함) | `lane_id_fix`, `lane_id_need` 5/`lane_id_window` 7 |
| 3차로 안 위치 | 위 + 카메라 보정 비중 2배 | `lane_fix_gain` 0.30, `lane_fix_heading_gain` 0.2 |
| 장애물 크기 | 앞뒤 0.7m 넘거나 폭 0.45m 넘으면 벽, 0.08m 안 되면 기둥·다리 → 버림 | `max_obs_len`, `max_obs_width`, `min_obs_size` |
| 막혔을 때 | 25cm 후진하며 꺾기 대신 **지나온 길 그대로 후진**. 후진하면서 계속 다시 계획해서, 옆 차로로 틀 공간까지 생기는 순간 멈추고 그리로 감. 한 번 최대 1.5m, 3번 | `recover_mode: trail`, `rollback_max_dist` |
| 차로 유지 | 차로 안에서 똑바로 갈 때 조향 = 0.5 회피 + 0.5 팀 차선 노드 곡률 (양쪽 선 보이고 같은 차로일 때만, 차로 바꾸는 중엔 0) | `lane_keep_blend` 0.5 |

`/avoid/state`에 `cam_lane`(카메라 차로 번호), `lane_id_fix_n`, `rollback`, `rollback_m`, `lane_blend` 추가.
`/lane/status`에 `line_left`, `line_right`({color, dashed, cov}), `lane_id` 추가. 디버그 화면에 "선 종류"와 3차선 구간 표시.

## 실차에서 확인할 것 (미검증)
- 점선 판단: `/lane/status`의 `cov`(선이 있는 행 비율). 실선 0.9 이상, 점선 0.3~0.7이면 정상. 아니면 lane_node `line_solid_cov`(0.8) 조정.
- 노란색 판단: `yellow` 값이 노란 선 0.5 이상, 흰 선 0.5 미만인지.
- 시뮬레이션(stress_sim 280개) 이전과 같게 전부 통과. 카메라 선 종류·벽은 이 시뮬레이션에 없음.
