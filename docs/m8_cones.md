# M8 라바콘 회피 (카메라 + 라이다)

좌측 직선(시작선 ~ 끝선 2,060mm, 차로 500mm) 구간. 차선 주행으로 다가가다가 구간에서는 **차선과 상관없이 콘 사이**로 달리고, 끝나면 다시 차선 주행으로 돌아온다.
위치는 규정집 IV장 순서(갈림길 → 라바콘 → 신호등)와 도면으로 정해지고, 구간 안 콘 배치는 "임의 배치"라 모른다.

## 1. 흐름

```
M2 갈림길 끝 ──차선 주행──▶ 좌하단 코너 ──▶ 시작선 300mm 앞 ──콘 사이 경로──▶ 마지막 콘 통과 ──▶ 차선 다시 잡힘 ──▶ M1 신호등
 [M8 sub ''] 콘을 미리 추적만          [M8 sub 'cones']                    [M8 sub 'handover']
```

| 단계 | 누가 운전 | 넘어가는 조건 |
|---|---|---|
| 접근 `''` | 차선 노드 (서행 0.13) | 도면 위치로 시작선 300mm 앞 (또는 시작선 800mm 안에서 차 앞 콘이 500mm 안) |
| 콘 `cones` | obstacle 노드 (0.15) | obstacle 노드 `cones_done` 또는 끝선 + 150mm 또는 2.7m 주행 |
| 복귀 `handover` | obstacle 노드 (구간 방향 직진, 차로 중심) | 차선 노드가 4틱 연속 차선을 잡음 또는 400mm |

- `cones` 동안 차선 노드는 `heading` 모드로 돌려 두고(출력은 안 씀), `handover`에서 `normal`로 바꿔 **내부 상태를 초기화**한다. 콘을 차선으로 잘못 따라간 기억을 버리기 위해서다.
- obstacle 노드 명령이 0.3초 넘게 끊기면 mission_node가 **차선 주행으로 대신** 달린다 (서면 15초 Time-out + 부분점수 손해).
- `params.yaml`의 `cones_source_ready: false`로 바꾸면 예전처럼 차선 주행으로만 통과한다.

## 2. obstacle 노드 안에서 (cone_core.py)

1. **콘 후보 (라이다)**: 이웃 점 간격 50mm로 덩어리를 나누고, 크기 140mm 이하만 남긴다. LIMO(폭 220)·벽은 여기서 빠진다. 가장 가까운 점에서 단면 반지름(30mm)만큼 뒤를 콘 중심으로 본다.
2. **추적 (월드 좌표)**: 위치 = `/odom` 이동 거리 + `/imu` yaw로 다시 적분 (`/odom` yaw는 12% 틀림). 3번 보이면 확정. 지나간 콘도 기억하므로 차 옆·뒤 콘까지 경로에 쓴다. 앞 콘에 가려 안 보이는 콘, 정면 ±90° 밖(시야 가장자리·뒤)으로 간 콘은 지우지 않는다.
   - **라이다 시야 약 240°(뒤쪽 가림)**: 콘은 앞에서 다가올 때 이미 잡혀 있으므로 뒤를 못 봐도 된다. 시뮬레이션에서 360°/240°/180° 결과가 같았다 (최소 여유 33/31/33mm). 라이다에서 120mm 안의 점은 차체로 보고 버린다 (`cones.cone_min_range_mm`).
3. **카메라 확인**: 확정·후보 콘의 바닥 위치를 BEV 호모그래피(`bev_limo.yaml`)로 이미지에 찍고 그 위 상자에서 주황색 비율을 잰다. 4번 이상 봤는데 주황으로 보인 게 25% 미만이면 **콘이 아니라고 빼고**(기둥·사람 다리), 나중에 주황으로 보이면 되살린다. 카메라는 "빼기"만 한다 (화면 아래로 지나간 가까운 콘은 라이다만으로 유지).
4. **구간 좌표계**: `cones` 시작 순간 고정. x = 구간 직선 방향, y = 왼쪽 +, 원점 = 그때 뒤차축.
   방향은 (1) 직선 구간에서 배운 'IMU yaw − 도면 방향' + 도면상 북쪽(90°) → (2) 그 순간 차선 노드가 본 차로 방향 → (3) 지금 yaw 순으로 쓴다. 로그에 `axis=…(route…)`로 나온다. 차로 중심 `y_lane`은 차선 노드의 `offset_mm`.
5. **경로**:
   - 좌우 콘 쌍(콘 간격 300~1000mm, 앞뒤 어긋남 400mm 이하, 사이에 다른 콘 없음)의 **중점**을 잇는다. 다른 쌍과 폭·중점이 크게 어긋나는 쌍은 버린다.
   - 짝 없는 콘: 쌍 중점 선보다 왼쪽이면 왼쪽 경계로 보고 통로 반폭만큼 오른쪽을 지난다. 쌍이 없으면 직전 경로에서 덜 움직이는 쪽으로. **한 번 정한 방향은 유지**한다. 쌍 줄 바깥 물체는 무시한다.
   - 첫 쌍 250mm 앞에 같은 높이 점, 마지막 콘 350mm 뒤에 차로 중심 점을 넣고, 촘촘히 나눈 뒤 콘과 차 중심 거리가 205mm(반폭 115 + 바닥 50 + 여유 40)보다 가까운 점은 밀어낸다.
6. **추종**: Pure Pursuit (뒤차축 기준 lookahead 260mm, 조향 지연 0.35초 보상). 목표점까지의 원호가 콘에 너무 가까우면 lookahead를 0.8 → 0.65 → 0.5배로 당긴다 (코너 안쪽으로 질러 콘 치는 것 방지). 넘겨받을 때 차선 주행 곡률에서 시작한다 (코너를 돌며 들어오므로).
7. **끝**: 뒤차축이 마지막 콘 + 150mm를 지나면(진입 후 1.2m 이상) `cones_done`. 콘을 하나도 못 봐도 진입 후 2.7m면 끝.

## 3. 실차 첫 확인 순서

1. **라이다 위치·방향** (`obstacle_node.laser_x_mm`, `laser_yaw`) — 가장 중요. 시뮬레이션에서 라이다 방향 2° 오차만으로 콘 여유가 15mm 넘게 줄었다.
   콘 하나를 차 정면 1m에 두고 `ros2 topic echo /obstacle/state --field cones` 대신 디버그 그림(아래 4번)에서 콘이 정면 1m에 찍히는지 본다. 뒤차축 ~ 라이다 중심 거리를 줄자로 재서 `laser_x_mm`에 넣는다.
2. **콘 실측**: 라이다 스캔 높이의 콘 지름 → `cones.cone_scan_radius_mm` (반지름), 바닥 지름 → `cones.cone_base_radius_mm`.
3. **카메라 확인 켜졌는지**: 노드 시작 로그 `camera check on`. 콘 앞에서 디버그 그림에 빨간 X가 생기면 주황 판정이 안 되는 것 → `cam_orange_min`을 낮추거나 `cone_core.orange_mask`의 H/S/V 범위를 실물에 맞춘다. 급하면 `camera_check: false`.
4. **디버그 그림**: `ros2 run rqt_image_view rqt_image_view /obstacle/debug/compressed` (M8 상태에서만 나옴)
   주황 원 = 확정 콘, 회색 = 확인 중, 빨간 X = 카메라가 뺀 것, 하늘색 = 좌우 쌍, 초록 = 경로, 분홍 = 목표점, 노란 점선 = 차로 중심
5. **구간만 연습**: 차를 앞바퀴가 시작선 50cm 앞에 오게 놓고
   ```bash
   ros2 launch autorace_bringup autorace.launch.py use_detector:=false
   ros2 topic pub --once /mission/set_state std_msgs/msg/String "{data: M8_CONES}"
   ```
   이렇게 하면 직선 구간에서 yaw 차이를 배울 기회가 없어서 구간 방향은 (2) 차선 방향을 쓴다. 한 바퀴 전체로 달릴 때 로그에 `route`가 나오는지도 꼭 확인.
6. **녹화로 다시 보기**: `bash src/autorace_bringup/scripts/record_bag.sh m8` 로 녹화 → 노트북에서 `ros2 bag play` + `ros2 run autorace_obstacle obstacle_node --ros-args --params-file ... -p bev_config:=...` 로 같은 디버그 그림을 볼 수 있다 (bag에 `/mission/state`가 있어야 함).

## 4. 튜닝 표

| 증상 | 바꿀 것 |
|---|---|
| 콘 사이에서 좌우로 흔들림 | `cones.lookahead_mm` 260 → 300 |
| 굽은 통로에서 코너 안쪽 콘에 가까움 | `cones.lookahead_mm` 260 → 220, `cones.speed` 0.15 → 0.12 |
| 콘에 너무 붙어서 지나감 (여유 부족) | `cones.clear_margin_mm` 40 → 60 (통로가 좁으면 효과 없음: 그땐 가운데가 최선) |
| 콘이 안 잡힘 / 늦게 잡힘 | `cones.cone_min_pts` 2 유지, `cones.cone_max_size_mm` 140 → 170, `laser_yaw` 확인 |
| 콘 아닌 것이 콘으로 잡힘 | 카메라 확인 켜기, `cones.zone_half_width_mm` 650 → 550 |
| 끝나기 전에 차선으로 넘어감 | `cones.done_margin_mm` 150 → 250 |
| 끝나고 코너에서 바깥으로 밀림 | `cones_handover_frames` 4 → 2 (차선 노드에 빨리 넘김) |
| 가운데 놓인 콘을 반대쪽으로 피하고 싶음 | `cones.single_tie_side: left` |

실행 중 바꾸기: `ros2 param set /obstacle_node cones.lookahead_mm 300.0` (ConeParams는 노드 시작 때 읽으므로 **재시작 필요**. `laser_*`, `cam_orange_min`은 바로 반영)

## 5. 시뮬레이션 (ROS 없이)

`src/autorace_obstacle/test/cone_sim.py`: 갈림길 끝 → 좌하단 코너 → 라바콘 구간 → 좌상단 코너를 가상 라이다(정면 240°, 0.5°, 10Hz, 잡음)와 차량 모델(조향 지연 0.3초, 최소 회전 반지름 0.53m)로 달린다. IMU 방향을 도면과 임의로 돌려 놓고, 구간 방향 2°·차로 중심 30mm 오차를 넣은 결과 (차체 직사각형 ~ 콘 바닥 원 최소 여유):

| 배치 | 최소 여유 |
|---|---|
| 직선 통로 500 | 67mm |
| 좁고 서쪽으로 치우친 440 | 31mm |
| 굽은 통로 460 | 35mm |
| 좌우 엇갈림 480 | 62mm |
| 왼쪽 줄 중간 2개 빠짐 | 58mm |

## 6. 한계 / 남은 일

- **"안쪽 경로"가 슬라럼이면**: 지금은 가운데 콘들을 전부 한쪽으로 피한다 (콘은 안 건드림). 좌우 교대로 지나가야 점수가 나오는 거라면 `plan_path`의 짝 없는 콘 처리에 교대 규칙을 넣어야 한다 → 운영측 답변 필요.
- 차로 안쪽에 콘과 비슷한 크기의 콘 아닌 물체가 있으면 카메라 확인에만 의존한다 (시뮬레이션에서 카메라 없이 슬라럼 + 기둥은 실패).
- 진입 순간 차가 아직 코너를 도는 중이라(시작선이 코너 끝 120mm 뒤) 첫 콘 쪽 여유가 가장 작다. 첫 콘이 시작선에 바짝 붙어 있으면 `cones.speed`를 낮출 것.
- 차선 노드가 접근 중 주황 콘을 노란 차선으로 볼 수 있다 (노랑 H 15~40, 주황 H 0~18). 실물로 확인 필요.
