# 11/19 진행 방향(dir) 뒤집힘 수정 — 가속도계 축 방향 한 번만 배우기

담당: 신윤서 (판단·FSM, 11/19 분담표 1번). 브랜치 `claude/dir-fix`.

## 문제 (실차 bag)
- 1119_08: 전진 중 31초 연속(231~263초) 후진으로 판정 → 도면 위치 s가 14,836 → 5,289 mm로 거꾸로 줄어듦.
  그 뒤 M2·라바콘 뒤 코너 미리보기·신호등 정지 위치가 연달아 틀어짐 (11/19 bag 보고서 새 문제 1).
- 로그: `가속도계 축 방향 배움: +x가 뒤`가 M7 전후진 중(142.7·146.7·164.3초)에 다시 찍힘.
- 오돔 거리 자체는 정확함 (11/19 캡틴 실측: 3 m에 약 8 mm). 틀린 건 거리의 **부호**.

## 원인 (코드)
- `motion_dir.AccelDirection`은 우리 `/cmd_vel`로 출발할 때마다 가속도계 축 방향(+x가 앞/뒤)을 계속 다시 배운다.
- M7처럼 짧게 전진·후진을 반복하면 반대로 보이는 출발이 쌓여 축 방향이 뒤집힌다.
  축이 뒤집히면 그 뒤 모든 전진 출발이 후진(`imu_acc`)으로 판정된다 (`route.motion_sign`은 근거 중 하나라도 후진이면 후진).

## 수정
- `AccelDirection(learn_once=True)`: 축 방향이 한 번 확정되면 다시 배우지 않는다. 반대로 보인 배움은 `n_ignored`로 세기만 함.
- 파라미터 `mission_node.accel_learn_once` (코드 기본 true + params.yaml true). false면 예전 동작.
- `motion_sign` 우선순위는 그대로 둠: 우리 명령이 전진이어도 조종기(RC)로 후진하면 가속도로 잡아야 해서 (기존 시험 SEQ의 의도).

## 바뀌지 않는 것 / 한계
- 출발 때 처음 배운 방향이 틀리면 계속 틀린다. 출발 로그에서 `+x가 앞/뒤`가 맞는지 확인할 것. 확실하면 `accel_sign`(1/-1)으로 고정 가능.
- 한 번의 출발에서 가속도 판정이 틀리는 것(다음 멈춤까지)은 막지 못한다. 축이 뒤집혀 '계속' 틀리는 것만 막는다.
- `limo_obstacle_avoid/motion_dir.py`(M7 재생 `m7_replay_core`가 씀)는 같은 코드 사본인데 **이번에 안 고침** (성유빈 담당). 같은 수정이 필요한지 확인 요청.
- 2번 코너(M7 초입) 위치 오차는 M7 이전이라 이 버그와 별개 (05·09 dir 불일치 1~2%).
